## 0.3.0

- **不再空白**：以前重开 DSH，面板要对着空气等 40 多秒（片单超过 30 分钟就阻塞重建）。现在磁盘上有旧片单就立刻给你看，重建挪到后台；后台换好了只在顶部弹一行「新的一批装好了」，点了才换，不会把你正在读的卡片抽走
- **快了**：决赛圈查详情改 4 并发、5 条字幕/评论改 3 并发（原来一条一条排队等）
- **三档刷新**：0–3 小时不动 / 超过 3 小时（你打开时）或 6 小时（自动）跑一次轻量探测 / 满 24 小时才完整重建。以前是每 30 分钟一次全量搜索 + 一次模型调用
- **熟人名单**：从点赞、稍后看、点开过的记录里认出「你自己选出来的人」。1 次互动 = 观察中，3 次 = 熟人。熟人的新片（3 天内）直接进候选并加权，靠的是「预测」而不是等互动数据成熟
- **防回音室**：片单里熟人来源最多 2 条（5 条时）。规则挑选和模型策展两条路径都收（模型那条曾实测挑出 3/5），11 条单测守着
- 修固定 UP 拉不到投稿：`/space/wbi/arc/search` 只做 WBI 签名会被风控挡回（游客态稳定 `-352`，偶尔直接返回 HTML 拦截页）。补上浏览器指纹参数 + `buvid4` + 全局 750ms 节流；拉失败时「关注」页会说人话，不再干瞪眼
- `history.json` 补存 `mid`；`feedback.jsonl` 同一条视频只记一次（之前一条能记 3 行，把熟人分数算虚了）
- 测试 83 → 123（新增熟人名单 / 三档刷新 / 回音室三组）

## 0.2.9

- 新增「多样性」：分数排序太确定，同一个池子每次推的都一样。现在前 5 名固定，剩下的按分数加权抽签；设置里 0–1 可调（0 = 老行为），种子记在 `stats.diversity` 里，出问题能重放
- 冷启动补数据（每轮 8 条）+ 缺互动数据时的临时加分（≤0.05，补过详情就失效）
- 新鲜度配额：`main` 里至少担保一条 3 天内、播放达标、贴轴的
- 互动数据 7 天过期重刷；播放增速用于「先补谁的数据」

## 0.2.8

- 修「新片永远排不进前 24」的补查闭环：搜索接口拿不到币/藏 → 新条目互动分垫底 → 只有初评前 12 名才回查详情 → 永远没数据。现在每轮先给 8 条贴轴新条目回查真数据（播放涨得快的优先），互动数据 7 天后自动刷新（每轮 3 条，播放高的先刷）
- 缺数据的条目在回查前按冷启动给一点临时加分（≤0.05，带 5 万播放门槛和标题党否决，补到真数据就撤）；策展候选行标注「数据:未补」，模型不再把没回查当成没人看
- 新鲜度配额兜底：main 里至少一条「3 天内 + 播放达标 + 贴轴」的新片，替换只动「轴上还有队友」的最低分
- 条目新增 `playGrowth`（播放增速），参与补查排序和冷启动微调；`stats` 新增 `detailCold` / `detailRefresh` / `coldStart` / `freshQuota` / `growthSeen`
- 测试 38 → 62；真实 8 轴配置实测：近 4 天进前 24 从 0 → 4，main ≤4 天从 0 → 3
