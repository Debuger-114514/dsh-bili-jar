# 设计：让冷门轴也能跑起来

> 状态：**规划中，未实现**。依据是 [`niche-tags-test.md`](niche-tags-test.md) 的实测数据。
> 2026-10-22 定稿方向：**只加 freshness 一个字段 + 一个自动放宽规则**，不做档位体系、不做短视频特化。

## 一句话

给每根轴加一个「内容会不会过期」的标记，系统按需自动判定、用户一键可改；某根轴凑不够 3 条时，自动把日期窗口放宽一档。

## 为什么不是全局调参数

实测（六个冷门词）说明两件事：

1. **贴轴几乎不卡人** —— 全放开后 20/20 都贴得上，卡人的是时长、播放、日期
2. **同一个规则不可能同时适配「时政」和「空洞骑士攻略」** —— 前者 14 天就过期，后者 2023 年的攻略今天照样有用

所以日期这件事必须**按轴**决定，其它参数保持全局。

## 一、唯一的轴字段：freshness

```yaml
丝之歌:
  terms: [丝之歌]          # 用户写的，不改
  aliases: []              # 扩词，带来源（见 §四）
  freshness: news          # news | evergreen  ← 新增的只有这一个
```

**向后兼容**：老配置没有这个字段 → 一律按 `news` 处理，行为与现在一致。

| | 日期窗口 | 时效分权重 | 差额去哪 |
|---|---|---|---|
| `news` | 14 天 | 0.10 | 不变 |
| `evergreen` | 不限 | 0.02 | 给「播放」和「小众 tag」，总权重仍 1.00 |

投票分曲线其余部分不动。时效分不砍到 0，是因为完全不算日期会让池子被最老最热的老片占满；0.02 的意思是「几乎不管，但同分时新一点的优先」。

## 二、预分配：按年龄中位数判定，不数条数

判据只有一条：**合格条目（不限日期）的年龄中位数 > 90 天 → evergreen。**

```
n_ok(不限) == 0        → 没货（保持 news，等扩词）
年龄中位 > 90 天       → evergreen（窗不设限）
年龄中位 ≤ 90 天       → news（14 天窗口；若 14 天 < 3 而 30 天 ≥ 3，本轮放宽到 30）
```

### 为什么不用「凑不凑得够 3 条」

实测七个词，年龄分布分成两堆，中间是空的：

| 轴 | 合格(不限) | 年龄中位 | >90 天占比 | 判定 |
|---|---|---|---|---|
| 空洞骑士 | 4 | 2052 天 | 100% | evergreen |
| vtuber | 1 | 2385 天 | 100% | evergreen |
| 丝之歌 | 4 | 361 天 | 75% | evergreen |
| 深蓝 | 8 | 26 天 | 25% | news |
| 时政 | 3 | 13 天 | 0% | news |
| kards | 4 | 5 天 | 25% | news |
| 术力口 | 5 | 5 天 | 0% | news |

条数会跟着搜索波动跳（丝之歌在一次重跑里 2↔4），**中位年龄不会跳**。
用「30 天内够不够 3 条」当判据，曾经把「时政」误判成 evergreen —— 它只是当天只有 2 条，内容其实很新。

### 两种标签可以并存

- `freshness: evergreen` + `内容极少（1 条）` —— vtuber 就是这种：唯一一条是 6.5 年前的科普，
  按年龄它确实是常青的，但这条轴没有真实供给。两个标签一起显示，不互相掩盖。

### 判定什么时候重算

每次建池都重算，日志记一行：

```
freshness: 丝之歌 news→evergreen（合格 4 条，年龄中位 361 天）
freshness: 时政   news（年龄中位 13 天，14 天 2 条 → 本轮窗口 30 天）
```

切换是可逆的（内容变新了会自动切回），所以不做「连续两次才生效」那种复杂化。

## 三、阈值与自动放宽

```
MIN_OK = 3        每轴「合格条目」下限；低于它才算这根轴没跑起来
```

「合格」= 过全部硬门槛（时长 / 播放 / 充电 / 回放 / 日期）且贴轴成功。

| n_ok | 动作 |
|---|---|
| ≥ 3 | 什么都不做 |
| < 3，扩词有候选 | 扩词（见 §四） |
| 扩词后仍 < 3，且是 `news` 轴 | 日期 14 → 30 → 90 逐级试，够 3 条就停 |
| 到底仍 < 3 | 标「这根轴没货」，说明卡在哪一关 |

**放宽只有一个维度（日期）**。时长和播放门槛不做逐轴放宽 —— 全局设置里本来就能调，用户真想放自己去改。

每级放宽写日志 `relax: 丝之歌 日期 14→30`，卡片上打「放宽」小标，点开能看放宽到哪一级。

## 四、扩词

### 触发

`n_ok < 3` 时触发。扩词优先于放宽：**扩词只改「搜什么」，不降质量标准；放宽改的是「什么算合格」，是降标准。**

### 候选从哪来

1. **组合搜索**：轴词 × 搜索结果里的高频共现词（`空洞骑士` + `丝之歌` → `空洞骑士 丝之歌`）
2. **tag 共现**：跟轴词一起出现的 tag（`Team Cherry`、`银河恶魔城`）
3. **B 站 搜索补全**（接口可用时）

### 谁决定

- **无歧义** → 自动写入 `aliases`（标记 `from: auto`），面板上可一键删
- **有歧义** → 必须问（§五）
- **手动**：轴那一行保留 `[＋ 加同义词]`，跟加兴趣轴一个交互

`aliases` 上限 6 个；**永远不改用户写的 `terms`**。

### 一个实测依据

「丝之歌」单独搜索返回 **0 条且不报错**（`code=0`），同一句重跑才有 20 条。单词搜索本身不稳，
而 `空洞骑士 丝之歌` 一次就 20 条 —— 这是「必须扩词」最硬的证据。

## 五、歧义分叉

### 怎么发现（纯规则，不花钱）

```
候选里出现两组 tag：
  组 A {三角洲, 射击, 角色}    40%
  组 B {汽车, 试驾, S07}       50%
两组共现 ≈ 0，且都 ≥ 30%
→ 判定：这个词有两个意思
```

### 怎么问

```
「深蓝」在 B 站上好像有两个意思，你要哪个？

  [ ] 三角洲行动 · 深蓝      2 条
  [ ] 深蓝汽车               3 条
  [ ] 两个都要（拆成两根轴）

  [先不选]  ← 默认，不点就不扩，本轮照旧
```

- 规则负责发现分裂，模型负责给两组起名和一句解释（一次调用约 ¥0.002）
- 选「两个都要」→ 拆成两根轴，各自 terms 不同
- **默认不选**：不猜、不打扰

## 五·五、先用 B 站 自己的搜索参数

实测（2026-10-22，`丝之歌`）发现：真正卡住冷门轴的不是我们的过滤，而是**我们只用了搜索的最基础形态**。

### 实测对比

| 排序 | 搜到 | 过「8–90 分 + 播放 1 万」 | 结果年龄中位数 |
|---|---|---|---|
| `totalrank`（现状） | 20 | 4 | 397 天 |
| `click` | 20 | 0 | 411 天 |
| `stow`（收藏） | 20 | 2 | 403 天 |
| `pubdate`（最新） | 20 | **0** | 0 天 |

「按最新」一条都不合格 —— 最近发的全是切片。内容集中在 2025 年（中位 397 天），与体感一致。

### B 站 搜索支持、但我们没用的参数

**`duration` 时长带**：1 = 10 分钟内，2 = 10–30 分，3 = 30–60 分，4 = 60 分以上。

```
duration=2  20 条全部落在 10–30 分，前排 905k / 875k / 1336k 播放
duration=3  20 条全部落在 30–60 分，前排 1157k / 377k / 1624k 播放
duration=4  20 条，但混进 1322 分钟的直播录像
```

**`order` 排序**：`totalrank` / `click` / `stow`（收藏）/ `pubdate` / `dm`。
`stow` 对常青内容尤其有用 —— 收藏量就是「值得反复看」的直接信号。

### 用法

| 轴类型 | 排序 | 时长带 |
|---|---|---|
| `news` | `totalrank` | 由轴的 min/max 推导 |
| `evergreen` | `stow`（或 totalrank + stow 各一轮） | 8–30 + 30–60 两带 |
| 一条都搜不到的轴 | totalrank | 先放宽时长带再说 |

- 每个时长带一次请求：**纯 HTTP，不花模型钱**
- 每轴每轮最多 2–3 次搜索（现状也是 3 次，基本不变）

### 优先级（重要）

```
① B 站 自己的筛选（时长带 + 排序）   ← 收益最大，零成本
② freshness（接不接受老内容）
③ 扩词（只在真的搜不到时）
```

扩词的必要性因此下降：`丝之歌` 不需要同义词，只需要 `duration=2/3 + totalrank`；
但它仍然需要 `evergreen`，因为那 4 条都在 200–400 天前。

## 五·六、种子扩散（解决「搜得到但被淹没」）

### 问题

用户点名的一条视频 `BV1t54y1a792`（空洞骑士官方最难挑战 无伤五门，33 分 / 108 万播放 / 2052 天前）：

| 通道 | 结果 |
|---|---|
| 搜索第 1 页（四种排序） | 都没有 |
| 搜索第 2–3 页 | 没有 |
| 搜索第 4 页 | 找到 |
| 按发布时间分段搜（2019–2022） | 那批内容对，但它仍不在首页 |

原因：`空洞骑士` 这个词被续作「丝之歌」的新内容挤满了，五年前的好视频排不进前 60 条。

### 解法：用「相关推荐」做内容图谱扩散

接口：`/x/web-interface/archive/related?bvid=<种子>`（一次 40 条，不需要登录）

实测（以 `BV1t54y1a792` 为种子）：

```
40 条相关 → 过时长+播放 15 条 → 贴轴 9 条
```

**冷启动也能用** —— 种子不必合格。用搜索结果里随便 3 条（都是 700 多分钟的攻略，本身全不合格）当种子：

```
3 个种子 → 去重 86 条 → 合格 10 条
其中含 BV1t54y1a792（就是搜不到的那条）
```

### 落在流水线里的位置

```
① 搜索（时长带 × 排序，每带 1 页）
② n_ok < MIN_OK → 拿搜索结果前 3 条当种子，各扩散一次（3 次 HTTP，5 秒）
③ 还不够 → freshness 判定（evergreen 就不卡日期）
④ 还不够 → 扩词
⑤ 还不行 → 报「没货」
```

- 成本：**3 次 HTTP + 5 秒**，不花钱、不用模型
- 种子可以缓存：每根轴记住最近用过的 1–3 个好视频，下轮优先从它扩散
- 用户也可以手动钉一条种子（「按这条找」），走同一个通道

### 什么时候不该扩散

- `news` 轴：图谱扩散会把老内容拉进来，与时效矛盾 → 只在 `evergreen` 或「没货」时用
- 相关推荐可能在同一簇里打转（都是「无伤五门」），所以还是要过时长/播放/贴轴三关

## 六、明确不做的（v1）

| 不做 | 原因 |
|---|---|
| 四档档位 profile | 把「轴的类型」做成了产品概念，用户得先理解分类才能加轴 |
| 短视频专用播放门槛 | 实测数据两极分化：vtuber 切片中位数 2.3 万，术力口短视频只有 1.2 千；定多少都要吵，换来一个可能没用的旋钮 |
| 短视频形态探测 + 单独打分曲线 | 同上；v1 只保留全局一套门槛 |
| 按轴覆盖时长 / 播放 | 全局设置里已有输入框，够用 |

保留的判断标准：**一个功能能不能用一句话讲清，且用户不必先学新概念。**
`freshness` 能（“这类内容会不会过期”）；短视频门槛不能。

### 留档：短视频的数据（以后要做得先解决这个矛盾）

| 词 | <8 分钟条数 | 中位播放 | ≥8 分钟条数 | 中位播放 |
|---|---|---|---|---|
| vtuber | 17 | 23,424 | 3 | 4,574 |
| 丝之歌·空洞骑士 | 11 | 24,535 | 9 | 35,838 |
| kards | 14 | 15,015 | 6 | 18,684 |
| 空洞骑士 | 9 | **2,287** | 10 | 714,773 |
| 术力口 | 12 | **1,260** | 8 | 16,024 |

短视频有两极，一套倍数套不住。真要做得先按轴标「形态」，否则就是拍脑袋。

## 六·五、加载动画：出去找 → 满载而归

### 素材

`art-source/maid-anim-sheet.png` 切成 12 帧（`assets/anim-out-1..6.png` / `anim-back-1..6.png`）：

- **上排**「出发探险」：5 帧走路（朝右）+ 1 帧举望远镜的「发现」
- **下排**「满载而归」：5 帧抱书走路（朝左）+ 1 帧闭眼「回到营地」
- 每帧约 300ms

两排朝向相反，**不需要 CSS 翻转**。

### 舞台

底部一条 40px 廊道，卡片列表在它上面，不被遮挡：

```
┌─────────────────────────────┐
│  卡片列表                    │
├─────────────────────────────┤
│                    [走走走→] │  出发：左侧走到右侧，出画
│  [←走走走]                  │  回来：从右侧走回，停在右端
└─────────────────────────────┘
```

### 节奏

| 段 | 内容 | 时长 |
|---|---|---|
| 出发 | 5 帧走路 × 300ms，从左走到右出画 | 1.5s |
| 发现 | 望远镜那帧静置（数据到得快就跳过） | 0.5s |
| 等待 | 她在画外；底部小字随进度更新「在翻… 3 条」 | 10–15s |
| 回来 | 从右侧走回，5 帧 × 300ms，停在右端 | 1.5s |
| 营地 | 抱书那帧静置 0.6s → 淡出，列表替换 | 0.6s |

**为什么停在右端**：她回来时朝左，停在右侧是「刚回到家放书」的位置，也和右下角的罐子呼应。

### 等待期间的两个提示（不让她凭空消失）

1. 底部小字随进度更新：`在翻… 3 条` → `在翻… 8 条` → `筛选中…`
2. 她在右边缘露半个身子，每 3 秒轻轻浮动一次

### 三种状态，只在真的要等时才走路

| 场景 | 动画 |
|---|---|
| 打开面板、有缓存 | **不走路**，直接出内容，角标「更新中」 |
| 点「换一批」 | 完整一趟 |
| 后台更新完成 | 走回来 + 列表平滑替换 |
| 没找到 | 空手回来（不显示抱书帧）+ 一句「这轮没找到」 |

### 体积

12 帧 × 约 20KB ≈ 240KB。可以用 128px 再压一档（约 120KB），对 1.2MB 的包可以接受。

## 七、落地形态与分阶段

| 阶段 | 内容 | 风险 | 依赖 |
|---|---|---|---|
| 1 | 搜索参数：`duration` 时长带 + `order` 排序（按 freshness 选） | 低（只改搜索词） | 无 |
| 2 | `freshness` 字段 + 年龄中位判据 + 两态开关 + 预设标注 | 低 | 1 |
| 3 | **种子扩散**（related）+ 种子缓存 | 低（只加一次 HTTP） | 1 |
| 4 | 本轮窗口放宽（日期）+ 日志与标记 | 低 | 2 |
| 5 | 扩词（只给真搜不到的轴） | 中 | 3 |
| 6 | 歧义检测 + 面板询问 | 中（交互） | 5 |

建议 1+2 一起做（当天能验），3 紧跟，4+5 放后面。

## 八、已定

| 项 | 值 |
|---|---|
| MIN_OK | **3** |
| 无歧义扩词 | **自动写入**，面板标来源，可一键删 |
| 默认 freshness | **news**（保守），按需自动切 evergreen |
| 短视频特化 | **v1 不做** |

## 九、还没想清楚的

- **歧义判定阈值**（30% + 共现≈0）：只试过「深蓝」一个词，得多收几个验
- **`silksong` 与 `丝之歌`**：同一轴的 alias，还是两根轴？倾向 alias
- **自动放宽到 90 天后的质量**：需要一轮实测，看模型会不会挑出垃圾
- **搜索结果里没有 `like` 字段**：互动率只在前 12 名补查详情之后才准，所以「用互动率救冷门轴」行不通，冷门轴只能靠贴轴和播放门槛
