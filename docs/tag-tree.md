# Tag 树：从数据里长出来

> 2026-10-21 凌晨。语料 `tools/crawl-tags.mjs` 抓 1412 条视频（平均 6.05 个 tag），
> 分析 `tools/tag-tree.mjs` 计算 DF / PMI / 标签传播聚类。

## 方法

1. **语料**：20 个种子词 × 4 页搜索。搜索接口自带 `tag` 字段，**抓 20 条视频只要 1 次请求**（84 秒抓完 1412 条）。
2. **共现**：同一条视频里的 tag 两两计数。
3. **PMI**：`log2( P(a,b) / (P(a)·P(b)) )` —— 把「到处都出现」的词压下去。
4. **聚类**：PMI ≥ 2 且共现 ≥ 3 的边构图上跑标签传播（LPA），12 轮。

## 三个结论

### 1. 「时政」这个词在 B站 是考公区的

搜「时政」出来的全是 `考编/国考/时政打卡`，不是国际新闻。真正的国际时政长在两簇：

- **地缘簇**：美国 / 中东 / 战争 / 军事 / 伊朗 / 以色列
- **人物簇**：特朗普 / 俄罗斯 / 乌克兰 / 泽连斯基 / 普京 / 俄乌

⇒ **轴不能再叫「时政」**，要拆成两个子轴，检索词也必须用实体（`特朗普`/`以色列`/`俄乌`），不能用类目词。

### 2. 组合轴天然会裂开

- `科技测评` → 电脑硬件 / 耳机 / 笔记本 / 手机评测（四簇）
- `健身教程` → 增肌训练 / 减脂跟练（两簇）

⇒ 一个「科技测评」标签下其实是四种完全不同的内容。树结构是必要的，不是锦上添花。

### 3. 泛 tag 检测有个坑：语料构成决定 DF

第一次跑，`健身` 以 16% 排在第一，被误判成「泛 tag」——其实是因为我们搜了 4 页「健身」。
⇒ 泛 tag 判定必须**按种子词归一化**（每个种子贡献相同条数），或者用 PMI 而不是裸 DF：
真正的泛 tag（`必剪创作`/`高能`/`vlog`）特征是**跟谁共现 PMI 都低**，而 `健身` 跟健身类 tag 的 PMI 很高。

## 落地形态

```
轴 = 一个簇（或几个簇的并）
  ├─ 检索词：簇内 DF 最高的 3 个词（自动轮换）
  ├─ 匹配词：簇内 DF ≥ 3 的全部词
  └─ 展示名：簇名（"国际时政 · 中东"）
```

好处：
- 检索词自动跟着数据走，不用手写
- 每天轮换子簇 → 天然解决「每天那五条不变」
- 卡片能写出「科技测评 · 耳机」这种具体标签
