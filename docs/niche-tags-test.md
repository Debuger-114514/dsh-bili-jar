# 小众 tag 实测报告

> 2026-10-22。目的：验证「冷门词」在当前规则下能不能进池，以及卡在哪一关。
> 工具：`node tools/tag-probe.mjs <词...>`（只读诊断，不写配置）

## 怎么测的

```bash
node tools/tag-probe.mjs 丝之歌 空洞骑士 kards 深蓝 vtuber 术力口
# 再跑两档对照：
node tools/tag-probe.mjs ... --days=0                                        # 只放开日期
node tools/tag-probe.mjs ... --days=0 --min-play=0 --min-minutes=0 --max-minutes=100000   # 只留轴匹配
```

每个词只搜第 1 页（20 条），走一遍建池的硬条件，数每一关砍掉多少。

## 判定标准

**硬门槛（全过才进池）**

| 关 | 条件 |
|---|---|
| 时长 | 8–90 分钟 |
| 播放 | ≥ 10,000 |
| 充电专属 | 排除 |
| 直播回放 / 录播 | 排除 |
| 日期 | 发布 14 天内 |
| 贴轴 | `axisSim` 要求轴的「每一组词」都命中（单组轴 = 命中任意一个词），且没有否决词 |

**判定口径**

- **通过**：默认参数下存活 ≥ 1 条，且能进决赛圈（分数排序前 24）
- **弱通过**：默认 0 条，但把日期放开后 ≥ 1 条
- **不通过**：放开日期仍为 0，或搜不到东西

**进池之后还会发生什么**（本次不测，但影响体感）

```
qualified → 打分（贴轴 .30 / 赞币藏 .39 / 时效 .10 / 小众 tag .06 / 字幕 .06 / 播放 .05 / 多轴 .04）
         → 按分数排序 → 前 24 进决赛圈 → 模型挑 5 条
```

一条视频「进池」不等于「被推给你」：小众轴池子里只有 4 条时，模型看到的候选也只有这 4 条。

## 结果

### 默认参数（8–90 分 / 播放 ≥ 1 万 / 14 天）

| 词 | 搜到 | 时长砍 | 播放砍 | 超期 | 贴不上轴 | **存活** | 判定 |
|---|---|---|---|---|---|---|---|
| 丝之歌 | 0\* | 0 | 0 | 0 | 0 | **0** | ❌ 不通过 |
| 空洞骑士 | 19 | 13 | 3 | 3 | 0 | **0** | ❌ 不通过（弱） |
| kards | 20 | 15 | 1 | 0 | 0 | **4** | ✅ 通过 |
| 深蓝 | 17 | 12 | 0 | 2 | 0 | **3** | ⚠️ 通过但语义混 |
| vtuber | 20 | 17 | 2 | 1 | 0 | **0** | ❌ 不通过（弱） |
| 术力口 | 20 | 14 | 3 | 0 | 0 | **3** | ✅ 通过 |

\* 第一次搜「丝之歌」返回 **0 条**（`code=0`，不是报错），重跑同一句才拿到 20 条 —— 搜索本身不稳定。

### 放开日期（其它条件不变）

| 词 | 默认 | 不限日期 | 增量 |
|---|---|---|---|
| 丝之歌 | 0 | 2 | +2 |

也就是说：**贴轴这一关几乎不卡人；卡人的是时长、播放、日期。**

## 逐词结论

### 1. 丝之歌 ❌

- 单独搜「丝之歌」拿到 **0 条**（有时候能拿到 20 条，搜索不稳）
- 换成「空洞骑士 丝之歌」立刻 20 条 —— **说明这个词不能单独当检索词**
- 20 条里：8 条 <8 分钟（切片、手机版安装教程），8 条 >90 分钟（十几小时全流程实况），8 条播放 <1 万
- 结论：**词太窄 + 长视频/切片两极分化**，两头都被 8–90 分钟砍掉

### 2. 空洞骑士 ❌（弱）

- 19 条里 13 条死在时长：既有 18–22 小时的全收集实况，也有 2–3 分钟的切片
- 放开日期后有 4 条活下来，说明**内容存在，是规则不合适**
- 结论：这类「单机游戏」轴需要更宽的时长区间（比如 5–240 分钟），否则只能捞到中间那一小撮

### 3. kards ✅

- 4 条：卡牌游戏实况 / 平衡补丁 / 卡组推荐，10–17 分钟，播放 1–10 万
- 有固定的赛季节奏（火山环带、钢铁赛），内容会持续产出
- 结论：**通过，属于"规则刚好合适"的类型**

### 4. 深蓝 ⚠️

- 5 条里混着两个完全不同的东西：
  - 《三角洲行动》里的角色「深蓝」（2 条）
  - **深蓝汽车**的试车视频（3 条）
- 结论：**单一词成轴会语义混**。要当轴用必须带限定（「三角洲 深蓝」或「深蓝汽车」）

### 5. vtuber ❌（弱）

- 17/20 死在时长：VTuber 的内容天然是 1–3 分钟切片
- 放开日期只剩 1 条，还是 **2385 天前**的「什么是 Vtuber」科普
- 结论：**这一类在当前规则下几乎不可能有产出**，需要单独放宽到「1 分钟以上」并接受短视频

### 6. 术力口 ✅

- 3 条都是周榜（Bili_Board 术力口周榜 / 传说曲周榜），11–14 分钟，播放 6–64 万
- 结论：**通过**。周榜类内容稳定、时长合适，是这个规则的理想型

## 三个结构性问题

1. **时长下限 8 分钟是最狠的一刀**：vtuber 砍掉 17/20，空洞骑士 13/19。游戏流程号和切片短视频都被这一刀切死。
2. **播放 ≥1 万对小众内容偏高**：刚才 six 个词里，播放砍掉的条数在 0–4 之间，不算最狠，但和时长叠加后杀伤很大。
3. **单词成轴不可靠**：丝之歌单独搜 0 条、深蓝语义混、vtuber 需要接受短视频形态。**轴不该只是一个词，而应该是一组「词 + 形态」**。

## 方案（供选择，暂不写代码）

### 方案 A：按轴覆盖规则（最小改动）

每个轴可以单独设：`minMinutes / maxMinutes / minPlay / maxDays`。

```yaml
丝之歌:    { terms: [丝之歌, 空洞骑士 丝之歌, silksong], maxMinutes: 240, minMinutes: 5, maxDays: 90 }
vtuber:   { terms: [vtuber, 虚拟主播, 切片], minMinutes: 1, minPlay: 3000, maxDays: 30 }
kards:    { terms: [kards], minMinutes: 5, maxDays: 30 }   # 现状就够
```

- 优点：彻底、可解释，用户自己调
- 缺点：要人填，冷启动麻烦

### 方案 B：自动放宽（无人值守）

建池时若某轴**合格条目 < 3**，自动按顺序放宽，直到够数或到顶：

```
① 日期 14 → 30 → 90 → 不限
② 播放 1 万 → 5000 → 1000 → 0
③ 时长下限 8 → 5 → 1，上限 90 → 240
```

- 优点：不用配置，所有轴受益；丝之歌/空洞骑士/vtuber 都能自己救回来
- 缺点：放宽后内容质量会降（比如播放 500 的切片），需要 UI 上标明「本轮为凑够条数放宽了」
- 建议：**只放宽到「能凑够 3 条」就停**，别一路放到 0

### 方案 C：词扩展（补搜索层）

轴 = 一组词，而不是一个词：

- 手动：轴上可以写别名（`丝之歌` / `空洞骑士 丝之歌` / `silksong` / `Team Cherry`）
- 自动：用搜索结果里的高频 tag 反推（`空洞骑士` 那 19 条的 tag 里 `丝之歌`、`Team Cherry`、`银河恶魔城` 都出现过）
- 组合搜索：`A B` 形式（B站 搜索支持空格组合），比单词精准
- 优点：从源头解决「搜不到/搜偏」
- 缺点：词表要维护；自动扩展可能引入噪声

### 我的建议：B + C 先做，A 作为兜底

- **B** 解决「规则一刀切」，收益最大、对现有 30 根预设轴无副作用
- **C** 解决「词太窄/语义混」：丝之歌、深蓝、vtuber 都是这类
- **A** 留给愿意手动调的人（也正好是我们已经有的 `axis-tree.json` 结构，加几个字段就行）

**B 的实现细节要看一个数**：某轴 14 天内合格条目 < 3 时放宽。要不要放宽、放宽到哪一档，最好**记到日志里**（`relaxed: 日期→90天`），不然用户会奇怪「今天怎么推了三个月前的视频」。

## 附：日期到底该不该管

数据看，日期放开带来的增量：

- 丝之歌 +2、空洞骑士 +4、vtuber +1、深蓝 +2、kards 0、术力口 0

**说明「日期」不是主要瓶颈，时长才是。** 但对「游戏 / 音乐 / 术力口」这类**内容不看时效**的轴，日期窗口确实只会帮倒忙 —— 一条 2023 年的空洞骑士攻略，今天看依然有用。

所以更准确的做法不是「所有轴都放开日期」，而是**按内容类型区分**：

- 时政 / 新闻类：时效就是质量，14 天甚至更短
- 游戏 / 攻略 / 音乐 / 杂谈：日期基本无意义，90 天或不限
- 这正好可以做成轴上的一个字段：`freshness: news | evergreen`
